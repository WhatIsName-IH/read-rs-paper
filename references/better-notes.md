# Better Notes 笔记与 Method Memory Card

## 来源与修订
生成前核对当前论文身份、原文、阅读记录与已确认的追问修订；以修订后的解释为准，不沿用已被纠正的旧总结。原文事实、机制推导、研究启发在对应内容中标明，不把推导或启发写成作者结论。

## 默认交付方式
默认用户自行复制保存。提供完整的 **原始 Markdown 源码**，包在一个标为 markdown 的代码块中，保留 LaTeX。告诉用户复制代码块内的内容，外层围栏不属于笔记。不要从已渲染数学或富文本反向拷贝。
用户明确选择 HTML 编辑或 Better Notes 模板导入时才转换到对应格式，并说明入口。原始 Markdown 正文、HTML 笔记源码、模板分享代码不可混用。模板用 Markdown 时需 `// @use-markdown`；不将该指令塞入普通笔记正文。
官方参考：https://github.com/windingwind/zotero-better-notes/blob/master/README.md 和 https://github.com/windingwind/zotero-better-notes/blob/master/docs/about-note-template.md 。涉及版本差异时查当前官方资料，不假定旧模板 API 仍可用。

## 数学与数据流
- 用户已确认必须保留数学分隔符：行内 `$X$`，独立公式用单独成行的 `$$` 包裹，公式前后保留空行。
- 原始 LaTeX 使用单个反斜杠。矩阵行分隔符 `\\` 等合法 LaTeX 不得误删；避免 JSON 转义残留造成命令双重反斜杠。
- 公式内部禁止 `<span>`、`</span>`、`<br>`、`&nbsp;` 等 HTML。中文段落、普通数据流箭头不放入数学块。
- 不输出复制渲染器产生的 HTML/MathML。不要用图片替代用户需要的公式源码。
- 删除 U+2028/U+2029、零宽空格等隐形格式字符；正常换行与中文标点保留。
- 用户要求单独公式时，提供包含 `$`/`$$` 的原始源码；只有用户明确要求公式编辑器的裸表达式才省略分隔符。

正确的独立公式源码示例（此例不代表任何当前论文的真实 Loss）：

$$
\mathcal{L}_{\mathrm{perceptual}}
=
\mathcal{L}_{\mathrm{content}}
+
\eta \mathcal{L}_{\mathrm{radio}}
$$

## 卡片固定字段与篇幅
按以下顺序生成，内容以核对事实为依据；字段保留，全文核对后确实缺失写“原文未报告”，材料不全或未核实写“尚未核实”，不适用写“本文不适用”。
1. **论文来源**：完整标题、作者/年份/发表来源、可用的真实论文/PDF/详细笔记链接。
2. **一句话记忆**：一句话含“问题、核心机制、作用”，不堆指标。
3. **核心问题**：1–2 句。
4. **方法流程**：按真实模块写 Input → ... → Output；可补简短步骤。
5. **三个关键词**：三个关键概念，各附极短作用。
6. **关键 Loss**：原始 LaTeX 公式、系数/关键变量和各项作用；复杂机制只保留重要项并链接详细笔记。
7. **为什么有效**：区分机制解释与实验支持，2–3 点。
8. **与其他方法的区别**：只比较已核实的方法或论文明确讨论的路线。
9. **对变化识别研究的启发**：1–3 点，明确属于扩展分析，不当作作者结论。
10. **30 秒复述版**：短段落，覆盖问题、方法和关键证据；不重复所有字段。
11. **关键证据**：已确认的章节、公式、图、表和页码；有真实可用链接时添加。
12. **关联知识**：已确认的相关论文/笔记与关系（共享机制、同一问题、对比等）；未找到时写“尚未建立关联”，不要虚构。
卡片以快速回忆为目标，不将整篇全文报告复制进来。A 在用户要求最终总结/Method 总结或复习笔记时生成；B 全文分析后默认生成。

## 论文与笔记关联
- 子笔记归属于论文条目，是实际保存位置；源码中的链接本身不会创建父子归属或 Zotero Related 关系。
- 论文条目标识与 PDF 附件标识、笔记标识是不同对象；BibTeX citation key 也不是 Zotero item key。
- 只有已取得 library 类型/ID、真实 item/attachment key 时才构建与其类型对应的链接。不得把用户库 URL 套到群组库，不得把论文 key 当成 PDF key。
- Better Notes 笔记链接优先使用工具/插件返回或用户复制的真实链接，不猜测 note URI 格式。不使用 `[[论文名]]` 冒充 Zotero 原生关联。
- 拿不到标识时仍交付正文，在代码块外简短说明缺哪些链接；不放貌似可点击的占位 URL。
- 支持时将卡片作为指定论文子笔记，连接详细笔记和相关知识笔记；自动写入仅在用户明确要求且工具支持时执行。默认不创建、覆盖或修改 Zotero 笔记。

## 代码块外的关联建议
每次最终复习卡之后，另列“建议关联的笔记”，每项包含笔记名或建议主题、关联理由、方向和是否已确认存在。只有存在并取得真实链接时才给可点击链接；建议新建的笔记以普通文字标注，不能当作已有对象。
优先选择与当前论文直接相关的 2–4 项；无充分依据时减少或说明暂无，不为数量凑关联：
- 本论文详细精读笔记：复习卡 → 精读笔记（出链），用于展开模块、公式与证据。
- 关键机制的概念笔记：复习卡 → 概念笔记（出链），用于补充理解机制。
- 同一研究问题的对比/主题汇总笔记：汇总笔记 → 复习卡（入链），用于横向比较。
- 经核实有具体关系的其他论文笔记：写清共享机制、不同假设或对照关系，避免只因关键词相同就关联。
简短说明：Better Notes 的 Link to 将所选笔记链接插入当前笔记，形成出链；Mention in 把当前笔记链接插入所选笔记，形成入链。关系图展示链接关系，不凭正文里的论文名称自动建立关系。生成建议不等于已建立链接，也不等于已创建 Zotero Related 或子笔记归属。
默认采用普通标题、段落、列表和标准链接，不输出未经环境验证的 `[!abstract]` 等 callout 标记。告诉用户复制代码块内部内容，而不是渲染后的正文。

## 检查与环境验证
交付前检查字段、公式分隔符、原始命令、HTML 污染、未知信息标记与链接来源。源码检查不能证明渲染正确。
首次有实际环境访问和授权时，使用含行内/独立公式、上下标、矩阵与真实链接的小笔记，检查显示、保存重开和链接跳转。没有做此测试就明确“源码已检查，实际显示尚未验证”。若显示失败，排查粘贴入口、版本和转换环节，不用承诺格式来掩盖失败。
